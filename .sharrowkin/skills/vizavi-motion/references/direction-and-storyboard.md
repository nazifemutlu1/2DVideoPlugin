# Режиссура и динамическая раскадровка

Этот файл переводит три механики Vizavi в практику 2DVideoPlugin. Он не заменяет `../../make-2d-video/references/story-breakdown.md`, а добавляет режиссёрский выбор до сборки.

## 1. Границы прохода

- Работай после транскрипта и до финальной фиксации `story/shots.json`.
- Сохраняй narration дословно: ни одного добавленного, удалённого или переставленного слова.
- Сохраняй базовый pacing: обычно 15–25 shots/мин, медиана 2–3.5 с, establishing shot на новую локацию.
- Не устраивай отдельный согласовательный марафон, если пользователь не просил. Покажи краткий выбор и продолжай.

## 2. Одна нить

Сформулируй:

- что действует;
- что меняется;
- какую мысль доказывает результат;
- почему зритель будет смотреть дальше.

Нить должна быть оригинальной для этого ролика. Не копируй последовательность `examples/reaction-time` под новым названием. Круг, портал или буква O — возможный приём, но не обязательный шаблон.

## 3. Варианты: 3–5 на смысловой beat

**Beat/сцена** — это непрерывный смысловой фрагмент: обычно 2–4 соседних shot или одна локация/действие, а не каждый микрокадр. Для 60-секундного ролика это обычно 5–10 beats; не размножай варианты на 20 микросклеек.

Для каждого beat предложи 3–5 вариантов, различающихся хотя бы одним существенным измерением:

- действие/причина и следствие;
- композиция и пространство: 2D, 2.5D-слои, 3D;
- метафора или способ показа;
- роль текста: подпись, участник действия, диаграмма;
- вход/выход и носитель перехода.

Смена цвета, шрифта или одного ease — не новый вариант. Если варианты отличаются только декором, это один вариант.

### Как выбрать

Выбирай по порядку:

1. Понятность смысла и связь с конкретной фразой.
2. Целостность с предыдущей и следующей сценой.
3. Оригинальность внутри этого ролика.
4. Реализуемость текущим API без новых зависимостей.
5. Стоимость сборки и рендера.

Покажи пользователю 3–5 коротких строк: вариант → что происходит → чем отличается. Затем одной строкой зафиксируй выбор и практическую причину. Не раскрывай внутренние рассуждения и не создавай отдельный planning-файл, если пользователь не просил; решение можно записать в `story/bible.md` или `notes` выбранных shots.

## 4. Карточка выбранного beat

Заполни для каждого beat до написания сцен:

| Поле | Что зафиксировать |
|---|---|
| Время и смысл | Интервал, главная фраза, роль в истории |
| Действие | Что было, что запускает изменение, реакция, результат |
| Локация | Set, mood, ключевой свет, окно/вид, 3–6 props |
| Слои | Небо → дальний → средний → пол → передний; depth для параллакса |
| Камера | Путь, цель, скорость, крупность, начало/конец |
| Оптика | Что реально делаем: `blurLayer`, ghosting, fov, fog; без ложных DOF/motion blur |
| Текст | Точная фраза, роль в действии, окно чтения, шрифт |
| Вход/выход | Тип перехода, что несёт склейку, совпадение силуэта/движения |
| Звук | SFX/amb, момент акцента, музыкальная секция |
| Риск | Главный технический или художественный риск и способ пробы |

## 5. Камера и глубина

### 2D

- Строй связную траекторию на весь beat: `x`, `y`, `z`, `r` — функции от `t`, а не набор одинаковых ease на каждом акценте.
- Разгон и торможение должны читаться. В активной фазе большой проезд может перейти в спокойную дугу или дрейф.
- Сопровождение героя совместимо с параллаксом окружения; не приклеивай все слои к одной скорости.
- На стыке проверяй позицию, направление и экранную скорость. Для монтажного cut непрерывная мировая координата не нужна; для continuous shot — нужна.
- Защищай силуэт героя, лицо и текст от случайного перекрытия.

### 2.5D

- Плоские слои на depth 0.1–1.8; камера раскрывает перспективу, перекрытия и параллакс.
- Не имитируй настоящую 3D-толщину там, где её нет.
- Передний blurred-слой (`blurLayer`, depth 1.5–1.8) помогает глубине, но не заменяет композицию.

### 3D

- Используй `T.orbit`/`T.dolly`, `fov`, туман, свет и перекрытия.
- Не обещай DOF/motion blur: их нет.
- Для реального объекта из примитивов сначала проверь масштаб, pivot, контакт и материалы, потом движение.

## 6. Типографика как действие

- Сначала спроектируй читаемую финальную раскладку, затем анимацию.
- Действие букв/слов должно иметь смысловую роль: сборка, маска, смена ширины, пространственное отношение, контакт с объектом.
- Используй `text()`/`measure()` и per-glyph/per-word код; `wordTime()` — для привязки к речи.
- Каждое обязательное слово получает окно чтения. Не ускоряй до нечитаемости ради ритма.
- Для кириллицы — Nunito/Playfair, не Fredoka.
- Не спасай темп удалением обязательных элементов или стенами текста.

## 7. Свет, материал, контакт

- Один ключевой источник на shot; 1–3 ярких акцента; тёмная середина кадра.
- Форма читается геометрией, нормалями, толщиной, contact shadow и перекрытиями. Блик и частицы не исправляют неверную конструкцию.
- У объекта есть вес: вход, контакт, реакция, затухание. Вторичные движения поддерживают главное, а не спорят с ним.
- Атмосфера почти в каждом shot: dust/rain/drops/fog/glow/lensStreak.

## 8. Звук и акценты

- Планируй `sfx`/`amb` вместе с действием, а не после.
- `at` — секунды от начала shot. Привязывай whoosh к ускорению/переходу, impact к контакту, pop/blip к появлению графики.
- Музыкальная секция задаётся в `music`; меняй mood/intensity на поворотах истории.
- Beat detection нет. Если используешь свою музыку, найди акценты слухом/по известным меткам и проверь в preview; не выдумывай точную карту по BPM.
- Не монтируй каждый бит. Речь, чтение и смысл важнее механической сетки.

## 9. Риск-проба

До полной сборки выбери **один** показательный риск:

- сложная 3D-камера;
- кинетическая типографика;
- параллакс с перекрытием;
- необычный переход;
- плотный UI-драг;
- имитация смаза/глубины.

Проверь его в реальном качестве:

```bash
node render.mjs --project projects/<slug> --stills t1,t2,t3
node render.mjs --project projects/<slug> --from A --to B --scale 0.5
```

Смотри кадры/движение сам. Если риск не оправдался, упрости постановку до полной сборки. Проба не заменяет ни раскадровку, ни финальную итерацию; полный рендер для неё не запускай.

## 10. Запись в shots.json

После выбора перепиши `story/shots.json` по базовой схеме:

```json
{
  "id": "s013",
  "start": 42.0,
  "end": 45.2,
  "line": "точная фраза",
  "scene": "Конкретное действие, композиция, камера, свет, переход",
  "set": "night_street",
  "bars": "wide",
  "in": {"type": "whip", "dur": 0.35, "dir": 1},
  "sfx": [{"at": 0.4, "name": "whoosh", "gain": -10}],
  "amb": {"name": "city", "gain": -24},
  "notes": "Выбранный вариант B: камера следует за героем, параллакс домов; без ложного DOF"
}
```

Правила:

- shots непрерывны: `end` предыдущего = `start` следующего;
- первый начинается с 0, последний заканчивается на `duration`;
- cut на границе фразы, за 0.1–0.2 с до её начала;
- `scene` — одно конкретное предложение, а не список тегов;
- `params` используй для чисел, нужных сцене;
- не добавляй поля, которых не понимает базовый engine, без необходимости.

## 11. Видео-референсы

Если пользователь дал файл или URL:

1. Фактически открой материал; не описывай его по заголовку.
2. Составь карту сцен/переходов с таймкодами: границы, крупности, слои, действие, камера, свет, звук.
3. Для важных стыков извлеки плотную последовательность и посмотри движение.
4. Разделяй: **видно/слышно в интервале → полезный принцип → собственное решение**.
5. Не переноси чужое видео, музыку, шрифт или модель без прав.

Если доступен только текст или poster, честно скажи об этом и не приписывай референсу невидимые свойства.

## 12. Проверка перед сборкой

- У каждого beat есть выбранный вариант и причина.
- Ни один shot не противоречит narration.
- Камера/слои/текст реально реализуемы текущим API.
- Нет ложных обещаний оптики или ассетов.
- Риск-проба выполнена или явно запланирована.
- Пользователь получил краткое резюме и не возражает.
