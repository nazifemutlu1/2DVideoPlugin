# Итерация, визуальный QC и экспорт

Это рабочая проверка, а не сертификат по наличию кода. Базовая инструкция `../../make-2d-video/references/render-qc.md` остаётся главной; здесь добавлены motion-specific проверки и честные статусы.

## 1. Первая сборка — черновик

Не показывай первую сборку как финал. Сначала:

1. Просмотри весь ролик на обычной скорости.
2. Разбери каждую сцену и каждый стык.
3. При звуке прослушай полный микс и нужные отдельные слои.
4. Запиши замечания в формате:

**интервал → наблюдение → причина → конкретная правка → повторная проверка**

Пример: `00:18–00:21 → герой теряется на тёмном фоне → rim light направлен от камеры, силуэт сливается → развернуть rim к окну и поднять контраст пола → пересмотреть stills и preview`.

Не имитируй итерации ради числа. Если дефектов нет, зафиксируй, что именно проверено.

## 2. Что проверять в изображении

- [ ] Идея и причинная нить считываются; герой узнаваем; есть развитие, а не скучное зависание.
- [ ] Каждый shot соответствует своей `line`; ключевое действие попадает на ключевое слово.
- [ ] Нет `MISSING SHOT` и красных `ERROR`; консоль рендера не сообщает ошибок сцен.
- [ ] Камера, крупность, перспектива и слои направляют внимание; скорости и стыки мягкие.
- [ ] В каждом shot есть осмысленное движение камеры и атмосфера; нет статичных провалов.
- [ ] Параллакс читается: передний/средний/дальний планы различаются масштабом, перекрытием и относительным движением.
- [ ] Типографика участвует в действии; обязательные слова читаются без паузы; нет стен текста.
- [ ] Rim light есть у освещённых фигур; персонажи стоят на земле, есть contact shadow, нет обрезки по краям.
- [ ] Одежда, signature-цвет и screen direction одинаковы внутри сцены.
- [ ] Moody value structure: 60–75% тёмной середины, 1–3 ярких акцента; цвета из `mood()`/`S()`.
- [ ] Форма, свет, материал и контакт убедительны; блик/частицы не маскируют неверную конструкцию.
- [ ] `blurLayer` и ghosting не названы DOF/motion blur; зритель не обманут.
- [ ] Текст в safe area, не под captions; числа совпадают с narration.
- [ ] Разнообразие: не больше 3 подряд одинаковых по типу/крупности shots; есть close-ups и inserts.
- [ ] 9:16: субъект в средней трети, ничего важного под captions и платформенным UI.
- [ ] Нет повторяющегося строба/вспышек как замены энергии; рискованные яркостные переходы проверены глазами.

## 3. Что проверять в движении

- [ ] Траектория камеры связная; нет рывков и одинаковых ease-in-out на каждом акценте.
- [ ] На стыках совпадают позиция, направление и экранная скорость там, где нужна непрерывность.
- [ ] Объекты имеют вход, контакт, реакцию и затухание; вторичные движения не спорят с главным.
- [ ] Кинетическая типографика не ускоряется до нечитаемости; окно чтения достаточное.
- [ ] Имитация смаза/глубины применена как акцент, а не на весь ролик.
- [ ] Быстрые фазы и границы сцен проверены в движении, а не только по still.

## 4. Что проверять в звуке

- [ ] Голос чистый и не перекрыт музыкой/SFX.
- [ ] Музыка ducked, ambience не гудит, нет щелчков, клиппинга и обрывов.
- [ ] SFX привязаны к действиям, а не насыпаны случайно; нет больше ~2 cue в один момент.
- [ ] Выбранные акценты совпадают с визуальными событиями; после speed ramp тайминги пересчитаны.
- [ ] Финальный микс прослушан; наличие AAC само по себе не доказывает качество.
- [ ] Если ролик задуман silent, звук действительно отсутствует; если музыка/SFX есть, это не называется silent.
- [ ] Помни: `audio/mix.py` требует `config.voiceover`. Без voiceover штатный финальный микс с музыкой/SFX не собирается.

## 5. Исправление причин

- Исправляй причину, а не симптом: не «добавить blur», а «foreground перекрывает лицо — сместить слой и уменьшить blur».
- После правки пересмотри изменённое место, соседние фазы и весь ролик.
- После упрощения сверься с брифом: нельзя принять «чище», если исчезли герой, текст, окружение или обязательное действие.
- Не переделывай вкусовые альтернативы бесконечно. Завершай, когда обязательное выполнено, существенные дефекты исправлены, а остальное — вкус.
- Не запускай полный рендер до preview и согласования. Для проверки используй sheet/stills/короткий preview.

## 6. Команды проверки

Из `2d-video/`:

```bash
node render.mjs --project projects/<slug> --sheet --scale 0.5
node render.mjs --project projects/<slug> --stills t1,t2,t3
node render.mjs --project projects/<slug> --from 0 --to 30 --scale 0.5
node render.mjs --project projects/<slug> [--workers N] [--format jpeg]
# from workspace root:
python tools/2dvideo.py mix --project projects/<slug>
```

- `--sheet` — по одному still на shot; открывай PNG и проверяй композицию.
- `--stills` — несколько моментов; проверяй движение и фазы.
- `--from/--to` — preview-фрагмент; смотри в темпе.
- Полный рендер — только после preview; в текущем DSH используй фоновый job (`bash`/`pwsh`), не `nohup`/`&`.
- `--format jpeg` ускоряет захват, но не меняет итоговый H.264.
- `--out` с относительным путём разрешается от cwd, а не от проекта; не используй вслепую.

## 7. Финальный decoded QC

Проверяй именно доставленный MP4, а не preview, HTML или исходные PNG.

```bash
ffprobe -v error -show_entries format=duration,size:stream=index,codec_name,codec_type,pix_fmt,width,height,r_frame_rate,nb_frames -of json out/<title>.mp4
ffmpeg -i out/<title>.mp4 -vf fps=1/10,scale=320:-1,tile=6x5 -frames:v 1 build/final_sheet.png
ffmpeg -i out/<title>.mp4 -af ebur128=framelog=quiet -f null -
```

Проверь:

- реальный кодек H.264, `yuv420p`, разрешение и ровный fps;
- число кадров и длительность совпадают с `story/shots.json`;
- аудиопоток присутствует, если он заявлен; AAC 192k — штатный mux;
- AV sync, начало, конец, границы сцен;
- контактный лист финального файла выглядит как ожидалось;
- полный просмотр и прослушивание финала.

`-shortest` в `mix.py` может обрезать более длинный поток. Если финал короче задуманного, проверь длительности видео и микса, не маскируй проблему повторным mux.

## 8. Формат и defaults

- Базовый default: 1920×1080, 24 fps, H.264 yuv420p, AAC при наличии voiceover.
- 9:16: 1080×1920; проверяй кадры и captions отдельно.
- 60 fps: только по явному запросу; сначала тест, затем обещание. Не называй файл 60 fps, если он 24.
- 4K: по запросу; дольше и тяжелее по памяти.
- Silent: только если бриф разрешает; не добавляй звук самовольно. Music/SFX-only финал без voiceover сейчас не собирается штатным `mix.py`.
- Явные параметры брифа важнее defaults. Не называй 4K/60 fps готовым, если фактический файл другой.

## 9. Честные статусы

Различай:

- **реализовано** — код/сцена написаны;
- **проверено запуском** — команда выполнена без ошибок;
- **видно в кадрах** — проверены stills;
- **проверено в движении** — просмотрен preview/фрагмент;
- **прослушано** — прослушан микс.

Непроверенное не получает PASS из параметров или общего впечатления. Если инструмент недоступен, назови конкретную невыполненную проверку и причину, покажи доступный артефакт с соответствующей маркировкой. Не выдумывай просмотр, запуск или эффективность.

## 10. Завершение

Ролик готов, когда:

- обязательное из брифа выполнено;
- существенные дефекты исправлены и перепроверены;
- финальный decoded MP4 просмотрен и, при звуке, прослушан;
- пути к файлам и честный статус сообщены пользователю.

Остановись после этого. Не запускай бесконечные вкусовые итерации без нового запроса.
